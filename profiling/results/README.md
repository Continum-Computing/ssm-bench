# Benchmark Results

This directory contains all benchmark results for the GPU-SSM mismatch study, organized by GPU platform and date.

## Directory Structure

```
profiling/results/
├── README.md                           # This file
├── manifest.json                       # Index of all result sets
├── t4-colab-2026-10-10/               # Tesla T4 results from Google Colab
│   ├── metadata.json                   # GPU specs, software versions, config
│   ├── benchmark_results.json          # Raw benchmark data (36 configurations)
│   ├── benchmark_summary.txt           # Human-readable summary
│   └── plots/
│       ├── latency_vs_seq_len.png
│       ├── bandwidth_utilization.png
│       ├── compute_utilization.png
│       └── roofline_model.png
├── a100-modal-2026-10-10/             # A100 results from Modal
│   ├── metadata.json                   # GPU specs, software versions, config
│   └── benchmark_results.json          # Raw benchmark data (36 configurations)
└── analysis/
    └── gpu_comparison_t4_vs_a100.md    # Cross-GPU analysis document
```

## Naming Convention

Result directories follow the pattern: `{gpu}-{platform}-{date}`

- **gpu**: GPU model name in lowercase (e.g., `t4`, `a100`, `h100`)
- **platform**: Execution platform (e.g., `colab`, `modal`, `local`)
- **date**: ISO 8601 date format `YYYY-MM-DD`

Examples:
- `t4-colab-2026-10-10` — Tesla T4 on Google Colab, October 10, 2026
- `a100-modal-2026-10-10` — A100 on Modal, October 10, 2026
- `h100-local-2026-11-15` — H100 on local machine, November 15, 2026

## File Descriptions

### `manifest.json`

Top-level index of all result sets. Contains:
- List of all available result sets with metadata
- Quick summary of key findings
- Pointers to analysis documents

### `metadata.json` (per result set)

Detailed metadata for a single benchmark run:
- **run_id**: Unique identifier
- **timestamp**: When the benchmark was executed
- **platform**: GPU specs and execution platform
- **software**: Python, PyTorch, CUDA versions
- **configuration**: Benchmark parameters (sequence lengths, state dimensions, etc.)
- **summary**: Aggregated statistics (average latency, utilization)
- **key_findings**: One-line summary of results
- **files**: List of files in this result set

### `benchmark_results.json` (per result set)

Raw benchmark data containing all measurements:
- Per-configuration results (latency, bandwidth, compute, arithmetic intensity)
- Statistical measures (mean, std, min, max, median, P95, P99)
- Hardware utilization metrics

### `benchmark_summary.txt` (per result set)

Human-readable summary generated by the benchmark runner. Contains:
- GPU specifications
- Benchmark configuration
- Average performance metrics
- Key findings

### `plots/` (per result set)

Visualization plots generated from the benchmark data:
- **latency_vs_seq_len.png**: Latency scaling with sequence length
- **bandwidth_utilization.png**: Memory bandwidth utilization
- **compute_utilization.png**: Compute unit utilization
- **roofline_model.png**: Roofline analysis (arithmetic intensity vs performance)

### `analysis/`

Cross-result analysis documents:
- **gpu_comparison_t4_vs_a100.md**: Detailed comparison of T4 vs A100 results

## How to Reproduce Results

### Prerequisites

- Python 3.11+
- PyTorch 2.0+ with CUDA support
- NVIDIA GPU (or cloud GPU access via Modal/Colab)
- matplotlib, numpy

### Running Benchmarks

```bash
# Install dependencies
pip install torch matplotlib numpy

# Run benchmarks (requires GPU)
python profiling/run_benchmarks.py \
  --seq-lens 512 1024 2048 4096 \
  --state-dims 64 128 256 \
  --input-dim 256 \
  --output-dim 256 \
  --dtype bf16 \
  --device 0 \
  --output profiling/results/{gpu}-{platform}-{date}/benchmark_results.json
```

### Generating Visualizations

```bash
python profiling/visualize.py \
  profiling/results/{gpu}-{platform}-{date}/benchmark_results.json \
  --output-dir profiling/results/{gpu}-{platform}-{date}/plots/
```

### Running on Modal (Cloud GPU)

```bash
# Install Modal
pip install modal
modal setup

# Run benchmarks on A100
python model/modal_benchmark.py
```

## How to Add New Results

1. **Create result directory**:
   ```bash
   mkdir -p profiling/results/{gpu}-{platform}-{date}
   mkdir -p profiling/results/{gpu}-{platform}-{date}/plots
   ```

2. **Run benchmarks**:
   ```bash
   python profiling/run_benchmarks.py \
     --output profiling/results/{gpu}-{platform}-{date}/benchmark_results.json
   ```

3. **Generate visualizations**:
   ```bash
   python profiling/visualize.py \
     profiling/results/{gpu}-{platform}-{date}/benchmark_results.json \
     --output-dir profiling/results/{gpu}-{platform}-{date}/plots/
   ```

4. **Create metadata.json**:
   - Extract metadata from `benchmark_results.json`
   - Add summary statistics and key findings
   - List all files in the result set

5. **Update manifest.json**:
   - Add entry for the new result set
   - Include quick summary of key findings

6. **Commit results**:
   ```bash
   git add profiling/results/{gpu}-{platform}-{date}/
   git add profiling/results/manifest.json
   git commit -m "results: add {gpu} benchmarks from {platform}"
   git push
   ```

## Key Findings Summary

### Tesla T4 (Google Colab)
- **SSM latency**: 100-200x slower than attention
- **Bandwidth utilization**: <0.2% of theoretical peak
- **Compute utilization**: <0.02% of theoretical peak
- **Arithmetic intensity**: 3-6 FLOP/byte (severely memory-bound)

### NVIDIA A100 (Modal)
- **SSM latency**: 1000-1500x slower than attention
- **Bandwidth utilization**: <0.1% of theoretical peak
- **Compute utilization**: <0.01% of theoretical peak
- **Arithmetic intensity**: 3-6 FLOP/byte (severely memory-bound)

### Cross-GPU Comparison
The performance gap **widens** on higher-end hardware:
- T4: SSM uses 0.02-0.15% of bandwidth
- A100: SSM uses 0.01-0.08% of bandwidth
- Attention scales dramatically on A100 (up to 9.3% bandwidth utilization)

This confirms the GPU-SSM mismatch is a **fundamental architectural issue**, not a temporary optimization problem.

## Data Integrity

All result files are:
- **Immutable**: Once committed, results are never modified. If a bug is found, a new result set is created with a corrected run.
- **Reproducible**: Each result set includes full metadata (software versions, hardware specs, configuration) to enable reproduction.
- **Self-contained**: Each result directory contains everything needed to understand and analyze the results.
